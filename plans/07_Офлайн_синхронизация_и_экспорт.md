# План 07: IndexedDB, outbox-синхронизация, CloudStorage и экспорт/импорт

> **Этап roadmap:** Этап 3 (Офлайн-first и миграция данных) · **Длительность:** 1 неделя · **Зависимости:** [План 03](03_Бэкенд_авторизация_и_БД.md), [План 05](05_Экран_Сегодня_и_свайп_механики.md), [План 06](06_Стрики_щиты_и_психология_привычек.md)
> **Результат:** приложение работает мгновенно без спиннеров даже в офлайне, все мутации пишутся в `IndexedDB` + `outbox`, синхронизируются пачками по `op_id`, лёгкие настройки резервируются в `CloudStorage`, а старые базы (`HD_SYNC`/JSON) безопасно импортируются с предпросмотром и откатом.

---

## 1. Ключевые задачи исполнения

1. **Единый store и слой хранения `IndexedDB` (`idb`):**
   - Ввести `store` (`getState` / `dispatch` / `subscribe`) с иммутабельным обновлением и разделением `saveState` на части (логи в `IndexedDB`, лёгкие настройки — в `localStorage`/`CloudStorage`).
   - Использовать `Map` для логов и типизированный слой для `checks`, версионировать схему (`migrateV1toV2`), валидировать при загрузке с fallback в безопасный режим.
   - Настроить одноразовую миграцию из старого `localStorage` в `IndexedDB`, автобэкап последних 3 состояний и ежедневный снимок.
2. **Офлайн-очередь (`outbox`) и синхронизация с сервером:**
   - Любая мутация: мгновенное применение в UI + запись в `IndexedDB` + добавление операции с `op_id = crypto.randomUUID()` в `outbox`.
   - Батчинг и отправка пачками при открытии, `visibilitychange`, `pagehide` / `freeze` / `beforeunload` (и `sendBeacon` при уходе).
   - Конфликт `(habit_id, date)` разрешается по последнему `ts`; таблица `sync_ops` на бэкенде гарантирует идемпотентность.
   - Интеграция `Telegram.WebApp.CloudStorage` как второго резервного хранилища настроек.
3. **Импорт и экспорт (без фейкового QR):**
   - Убрать фейковый QR из MVP; ссылку `#sync=` перевести на серверный токен (с `exp`, HMAC-подписью и `checksum`).
   - Заменить устаревшие `escape`/`unescape` на `TextEncoder` + base64, `execCommand('copy')` на `navigator.clipboard.writeText` с очисткой буфера через 30 с (опционально для токенов).
   - Импорт `HD_SYNC` / `JSON` с проверкой схемы (до 5 МБ), дедупликацией ID, dry-run предпросмотром («новых / обновлённых / конфликтных») и откатом.
   - Экспорт в `JSON` (с `version` и `checksum`), `CSV` и `Markdown` (с оглавлением и таблицами по месяцам) через общий `downloadFile(blob, name)`.
   - Удалить мёртвое поле `state.logs[k].gentle`.

## 3. Критерии готовности (Definition of Done)

- Чек-ины в режиме авиаполёта сохраняются в `IndexedDB` + `outbox`, а при восстановлении сети уходят на сервер без дублей (`sync_ops`).
- Данные из старого `Habit Diary (5).html` (`localStorage` / `HD_SYNC`) импортируются с предпросмотром и без потери кириллицы/эмодзи.
- Битый JSON/токен не ломает приложение (покрыто тестами `applyImportKey`), есть откат и восстановление из автобэкапа.
