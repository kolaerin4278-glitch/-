## 3. Что переиспользуется, а что обязательно переписывается

**Переносится из прототипа почти 1:1:**
5 экранов (Сегодня / Ритуалы / Анализ / Мастерство / Опции), свайп-карусель + нижний «остров» навигации, План Б, свайп-чек-ин, пульс энергии 1–5, фильтры по сферам, аккордеон завершённых, стрики, «Костёр» (% дня), щиты, граница суток, ритуалы-цепочки с таймером и мини-плеером, аналитика и PNG-постер, полка мастерства 60 дней, капсула времени, инкогнито, экспорт/импорт.

**Обязательно переписывается:**
1. `localStorage` одним ключом → IndexedDB + сервер + журнал операций `outbox` (План 07).
2. Отсутствие бэкенда → API + Postgres + валидация `initData` (План 03).
3. Фейковый QR и нерабочая `#sync=`-ссылка → убрать фейковый QR из MVP, починить ссылку через БД (План 07).
4. Захардкоженная дата «Среда, 11 нояб.» → вычисление через `Intl.DateTimeFormat` с кэшем (План 05).
5. `setInterval(1000)` в таймере → дельта по монотонному времени `performance.now()`/`Date.now()` (План 09).
6. Списание щита без проверки `shielded` → идемпотентная проверка на сервере (План 06).
7. Нет «Духа» в фильтре и нет редактирования привычки → добавить фильтр и экран редактирования (Планы 04, 05).
8. `new Date(dKey)` как UTC → даты строкой `YYYY-MM-DD` + `Intl` (План 05).
9. Монолитный `<script>` (~1 500 строк) → ES-модули + TypeScript + тесты (Планы 02, 06, 11).

## 4. Целевая архитектура и модель данных

```text
Telegram (iOS / Android / Desktop / Web)
        │  initData (HMAC-подпись)
        ▼
Mini App (Vite + TS + нативный CSS, Cloudflare Pages / Netlify, HTTPS)
  ├─ UI: модули вместо одного HTML-файла
  ├─ Стейт: store + IndexedDB (idb) + outbox
  ├─ Telegram SDK: themeParams, MainButton, BackButton, HapticFeedback,
  │                CloudStorage, shareToStory
  └─ API-клиент (fetch, ретраи, идемпотентность по op_id)
        │
        ▼
Backend (Node 22 + Fastify, или Supabase) + Postgres
  ├─ проверка initData (HMAC-SHA256, hash, auth_date, TTL)
  ├─ REST: habits / checkins / day_logs / rituals / settings / analytics
  ├─ сервис стриков и щитов (единый источник правды)
  └─ планировщик напоминаний (cron + очередь)
        │
        ▼
Telegram Bot (grammY)
  ├─ /start → кнопка-меню, открытие Mini App
  ├─ вечерний дайджест с inline-кнопками
  └─ напоминания + «не пропускай дважды» + капсула после 2 пропусков
```

**Таблицы БД (MVP):**
- `users`: `tg_id`, `tz`, `day_boundary_hour`, `created_at`, `plan`
- `habits`: `id`, `user_id`, `title`, `icon`, `sphere`, `type(binary/counter)`, `trigger`, `norm`, `plan_b`, `keystone`, `incognito`, `capsule`, `archived_at`, `deleted_at`, `sort`, `created_at`, `updated_at`
- `day_logs`: `user_id`, `date` (`YYYY-MM-DD`), `energy`, `shielded`, `note`
- `checkins`: `user_id`, `habit_id`, `date`, `status(full/plan_b/skip/counter)`, `value`, `skip_reason`, `ts`, `op_id`
- `rituals` / `ritual_steps`: `id`, `user_id`, `title`, `icon`, `steps[]` (`title`, `minutes`, `order`)
- `settings`: `user_id`, `haptic`, `notifications`, `digest_time`, `theme`
- `sync_ops`: `op_id`, `user_id`, `payload`, `applied_at`

## 5. Границы MVP и метрики приёмки

| Входит в MVP (Планы 01–11) | Отложено в бэклог (План 12) |
|---|---|
| Привычки + План Б + энергия + стрики + щиты | Соцсеть, комнаты, рейтинги |
| Ритуалы + таймер, переживающий блокировку | Голосовые капсулы |
| Базовая аналитика + PNG-постер в Stories | 7-карточные «Итоги месяца» |
| Бот: дайджест, напоминания, капсула после 2 пропусков | Платежи и подписки (Telegram Stars) |
| Офлайн-работа + outbox + импорт старой базы | Полный CRDT, шаринг привычек |
| Смена границы суток, часовые пояса | Виджеты, Apple Watch, Shortcuts |
| Доступность WCAG 2.2 AA и перф-бюджет | Тёмная/светлая темы сверх `themeParams` |

**Целевые технические метрики (проверяются в Плане 11):**
- Lighthouse Performance: `≥ 90` · Accessibility: `≥ 95` · LCP: `≤ 2.5 с`
- JS (gzip): `≤ 60 КБ` · CSS (gzip): `≤ 15 КБ`
- Нарушения `axe`: `0` · Покрытие тестами `computeStreak`: `100%`
